# Контекст для ИИ-ассистента (MadMarket Terminal)

Этот файл создан специально для быстрого погружения ИИ-агента в проект. Прочитай его при старте новой сессии, чтобы не сканировать весь проект заново.

## 1. Суть проекта
Высокопроизводительный консольный торговый терминал (Courtsiding/Live Betting) для брокера Mollybet (API MadMarket).
Терминал работает через постоянное HTTP/2 соединение для отправки ордеров и WebSocket для стриминга котировок (тикер + PMM).
Стек: чистый `Node.js` (`node:http2`, `node:readline`, `node:events`), без тяжелых фреймворков.

## 2. Карта модулей (Где что лежит)

* **`src/ui/terminalUI.js`**
  Отвечает за отрисовку интерфейса. Работает в `rawMode`. **Критическое правило:** Запрещено использовать обычный `console.log` — он сломает сетку HUD. Логика отрисовки строгая, многострочная, с ANSI-цветами. Поддерживает горячие клавиши (переключение рынков, выставление ставки, взведение купонов).
* **`src/core/executionEngine.js`**
  Мозг исполнения заявок. Отвечает за: выстрел (fire), debounce, расчет проскальзывания (`limitPrice`), срез ставки по лимиту БК (stake clamp) и асинхронный трекинг ордера (`IN_FLIGHT` -> `DONE` / `REJECTED` / частичное исполнение).
* **`src/core/stateManager.js`**
  Хранилище стейта. Изолирует котировки для 1-го тайма (HT) и всего матча (FT). Отслеживает предвзведенные купоны (`armedBetslips`), лимиты ставок (`maxStake`) и активные коэффициенты из разных источников (PMM vs общий тикер).
* **`src/adapters/mollybetAdapter.js`**
  Адаптер для HTTP/2 взаимодействия с API. Занимается предвзведением купонов (`POST /v1/betslips/`), отправкой ордеров (`POST /v1/orders/`), парсингом `got_stake` и фильтрацией букмекеров (обычно терминал работает строго по `pin88`).
* **`ARCHITECTURE_CONSTRAINTS.md`**
  **ОБЯЗАТЕЛЕН К ПРОЧТЕНИЮ ПРИ ИЗМЕНЕНИИ БИЗНЕС-ЛОГИКИ.** Содержит жесткие инварианты системы: квоты брокера (не более 4 открытых купонов), приоритизацию котировок, правила изоляции таймов.
* **`test-runner.js`**
  Кастомный фреймворк с 36 архитектурными юнит-тестами. Покрывает квоты, лимиты, парсинг, защиту от выстрелов в закрытую линию.

## 3. Критические инварианты и архитектурные решения

1. **Срез ставки (Stake Clamp):** Ставка пользователя не меняется глобально, но перед отправкой срезается до локального лимита исхода (`min(activeStake, slip.maxStake)`).
2. **Частичные исполнения:** Если ордер закрыт с `got_stake > 0`, но `close_reason != order_filled`, он считается `DONE` с флагом `partial`, а не `REJECTED`.
3. **Строгий фильтр БК:** В `TerminalUI` не должны просачиваться котировки от сторонних БК (например, SBO, если мы работаем по pin88). Если линия pin88 закрыта, HUD отображает `0.00 (ЗАКРЫТО)`, даже если в общем WS-канале есть котировки других контор.
4. **Переключение режимов:** Разделены периоды (FT/HT) и режимы рынков (MAIN/ITB). При смене режима/матча старые купоны удаляются (`DELETE`), чтобы не упереться в лимит брокера.
5. **История ставок и PnL:** Источником правды является `getOrdersHistory`, а не локальный кэш `ExecutionEngine`. Нормализатор статусов (`orderNormalizer.js`) сам рассчитывает реальный стейк (`effStake`) и кэф (`effPrice`) по массиву `bets`, так как статус верхнего уровня `failed` иногда приходит вместе с `close_reason: "order_filled"` (ошибка API Mollybet).
6. **Выбор линии ИТБ (tahou):** Для ИТБ используется `selectionMode = 'lowest'` (берем наименьший доступный тотал с кэфом > 1.0, например 0.5), тогда как для общего тотала (ahou) берется линия, максимально близкая к кэфу 1.95 (`even_money`).
7. **Поиск в меню:** Поиск реализован без отдельного поля ввода (перехватывается ввод `[a-zA-Z0-9 а-яА-ЯёЁ.-]` прямо в меню). Символы `\r` и `\n` строго исключены из перехвата поиска во избежание конфликтов с Enter.

## 4. Памятка для ИИ
* **Всегда** запускай `node test-runner.js` после изменения логики в `core` или `adapters`.
* **Никогда** не выводи мусор в `stdout`. Для отладочной информации используй файл логов `terminal.log` (через `logger.info`, `logger.warn` и т.д.).
* Код должен быть оптимизирован на микросекунды. Никаких тяжелых синхронных блокировок в `ExecutionEngine`.
* Сетка HUD жестко регламентирована. Обязательно соблюдай пустые строки и порядок вывода блоков в `renderHud()`, чтобы интерфейс не скакал при обновлении кадров.
