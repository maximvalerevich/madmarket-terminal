# Руководство по развертыванию на сервере (MadMarket Terminal)

Данное руководство описывает процесс установки, настройки и запуска терминала на удаленном сервере (Ubuntu/Debian, CentOS или Windows Server).

## 1. Системные требования

- **ОС**: Любой дистрибутив Linux (рекомендуется Ubuntu 22.04/24.04) или Windows Server.
- **Node.js**: Версия 18.0 или выше.
- **Сетевой доступ**: Исходящий доступ к `edge.madmarket.io` по портам 443 (HTTPS) и WSS (WebSocket).
- **Терминал**: Поддержка ANSI-цветов (по умолчанию есть во всех современных SSH-клиентах, таких как PuTTY, MobaXterm, Терминал MacOS/Windows).

---

## 2. Установка на Linux (Ubuntu/Debian)

### Шаг 1. Установка Node.js и Git
Подключитесь к серверу по SSH и выполните команды:
```bash
# Обновление пакетов
sudo apt update && sudo apt upgrade -y

# Установка curl и git
sudo apt install curl git -y

# Установка Node.js (рекомендуется LTS версия, например 20.x)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# Проверка версий
node -v
npm -v
```

### Шаг 2. Клонирование репозитория
Скачайте проект из вашего GitHub репозитория:
```bash
git clone https://github.com/ВАШ_АККАУНТ/ВАШ_РЕПОЗИТОРИЙ.git madmarket-terminal
cd madmarket-terminal
```

### Шаг 3. Установка зависимостей
Установите необходимые NPM-пакеты (хоть проект и написан почти без внешних зависимостей, нужно инициализировать `ws`):
```bash
npm install
```

---

## 3. Настройка аккаунта (config.json)

Файл `config.json` игнорируется Git'ом в целях безопасности, поэтому на сервере его нужно создать вручную.

1. Скопируйте пример конфигурации:
```bash
cp config.example.json config.json
```

2. Откройте `config.json` в любом текстовом редакторе (например, `nano` или `vim`):
```bash
nano config.json
```

3. Заполните конфиг вашими актуальными данными для подключения к Mollybet. **Внимание:** `sessionToken` имеет свойство истекать, поэтому перед боевой сессией его нужно актуализировать.
```json
{
  "baseUrl": "https://edge.madmarket.io",
  "wsUrl": "wss://edge.madmarket.io/cpricefeed/",
  "sessionToken": "ВАШ_АКТУАЛЬНЫЙ_ТОКЕН_АВТОРИЗАЦИИ",
  "instanceId": "ВАШ_INSTANCE_ID",
  "accounts": [
    ["pin88", "ВАШ_ЛОГИН_АККАУНТА_В_PIN88"]
  ],
  "adaptiveBookies": ["pin88"],
  "defaultStake": 5.0,
  "stakeStep": 10.0,
  "defaultCurrency": "EUR",
  "slippagePct": 0.03,
  "defaultDuration": 15,
  "debounceMs": 2000,
  "dryRun": false
}
```
*Для сохранения в `nano`: нажмите `Ctrl+O`, затем `Enter`, для выхода — `Ctrl+X`.*

## 4. Запуск терминала

### Обычный запуск (для работы через SSH)
Если вы хотите просто поработать в терминале прямо сейчас:
```bash
node index.js
```
Чтобы выйти, нажмите `Q` или `Ctrl+C`.

### Использование tmux или screen (Рекомендуется)
Если вы запускаете терминал на сервере и хотите, чтобы он **продолжал работать** при обрыве SSH-соединения или закрытии консоли (например, для режима "Ожидания фида"), используйте утилиту `tmux`.

```bash
# Установка tmux (если нет)
sudo apt install tmux -y

# Создание новой сессии с именем "terminal"
tmux new -s terminal

# Внутри tmux запустите терминал
node index.js
```

**Горячие клавиши tmux:**
- Чтобы **отсоединиться** от сессии (оставив терминал работать в фоне): Нажмите `Ctrl+B`, затем отпустите и нажмите `D`.
- Чтобы **вернуться** в работающую сессию при следующем SSH подключении: `tmux attach -t terminal`

---

## 5. Просмотр логов на сервере

Терминал пишет системные логи в файл `terminal.log`. Чтобы следить за ними в реальном времени, откройте второе окно SSH (или новую панель в tmux) и выполните:
```bash
tail -f terminal.log
```
Это позволит вам видеть сетевые пинги и ошибки WS без прерывания боевого HUD'а.
